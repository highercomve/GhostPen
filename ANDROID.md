# Single-window mode, and GhostPen on Android

Two linked pieces of work:

1. **Single-window mode** (`Settings → General → Interface`): every page lives
   in one app window with navigation, instead of today's five floating windows.
   Opt-in on desktop, the only mode on Android.
2. **An Android build** that uses single-window mode, and Android's own entry
   points in place of the tray and global hotkey: the text-selection menu, the
   share sheet, a Quick Settings tile, launcher shortcuts and (later) the
   GhostPen keyboard.

As with the rest of the port (PLAN.md), what Oriel lacks is added to Oriel,
not worked around here.

## What exists today

- `src/main.zig` registers six windows (`settings`, `playground`, `meetings`,
  `summary`, `dictation`, `captions`) plus `main` (the menu). Everything goes
  through `showWindow(label, center)`.
- `frontend/src/App.tsx` already routes by hash (`#/settings`, …) with each
  page in its own lazy chunk, so one window can show every page.
- `android/` was generated by `oriel android init` (Oriel 0.19.1) and isn't
  committed; `build.zig` has no `.android` block yet, and its
  `versionName` (0.2.19) is stale.
- Oriel on Android today: WebView windows, mic audio service, dictation
  through the system recognizer, ggml on GPU/NPU, **one** Quick Settings tile
  (`.android.tile`), the Oriel keyboard (`.android.input_method` →
  `oriel.android.commitText`), app-level Kotlin (`.android.sources`,
  `.android.hooks`).
- Not in Oriel on Android yet: receiving shares (`oriel.share` receives only on
  Windows, macOS and iOS), `ACTION_PROCESS_TEXT`, launcher shortcuts.

## 1. Single-window mode

### Setting

`interfaceMode: "windows" | "single"` in `Settings` (camelCase, like the rest),
default `"windows"`; forced to `"single"` on Android and hidden there.
Changing it applies on the next start (simplest: no live re-registration of
windows), and Settings says so.

### Frontend

- `Shell.tsx`: the app frame for single mode. Sidebar on wide windows, bottom
  tab bar under ~600 px (phones, narrow desktop windows). Sections: Actions
  (the menu), Playground, Meetings, Summary, Captions, Dictation, Settings.
- `App.tsx`: in single mode, wrap `Page` in `Shell`; in windows mode, unchanged.
  The mode comes from settings at load (or a `?mode=single` query on the URL
  the window is opened with, so the first paint is right).
- Pages written for small fixed windows need to work full-size and at phone
  width: Settings (540 px today) and Meetings (1040 px) are the two extremes.
  Captions and Dictation get pages too (live transcript panel, big mic
  button), used when they're set not to float.
- Menu as a page: shows the captured text (editable), the actions, the result,
  and Copy / Replace / Share buttons instead of auto-paste.

### Backend

- Register one window, `app` (`index.html?mode=single#/actions`), resizable,
  remembered size, `hide_on_close` only where there's a tray.
- `showWindow(label, …)` becomes the router: in single mode it shows `app` and
  emits `ghostpen://navigate` with the route; the page switches. Every caller
  (tray, second-instance flags, commands) keeps working unchanged.
- Events sent with `emitTo(label)` to a specific window need a single-mode
  target (`app`); audit every `emitTo`.

### The hotkey in single mode (desktop)

The hotkey opens the single window on the Actions page (`#/actions`) with the
captured selection; no separate popup. Paste back keeps working the way the
menu does today (`pasteFromWindow`): **Replace** hides the app window, focus
goes back to the app the text came from, and the result is pasted. **Copy**
copies and leaves the window as it is. The other hotkeys and tray items open
their own page in the same window (Dictation, Captions, …), unless that page
is set to float (below).

### Floating captions and dictation

Captions and Dictation can float in either mode: a per-feature setting,
`captionsFloat` / `dictationFloat` (default on). When on, they keep today's
transparent always-on-top overlay windows (`captions`, `dictation`), even in
single mode; when off, they're pages in the app window. So single mode
registers `app` plus whichever overlays are enabled.

On Android, floating works differently (Oriel supports none of it yet:
`always_on_top` is ignored there):

| Way | Fits | Cost |
| --- | --- | --- |
| **Picture-in-picture** (`enterPictureInPictureMode`, Android 8+) | Captions: a small floating, movable, always-on-top window with the live text; no permission | No typing or scrolling inside it (touch only opens or closes it), one PiP at a time, and the app's activity is what shrinks: needs its own activity for captions |
| **Overlay window** (`SYSTEM_ALERT_WINDOW`, `TYPE_APPLICATION_OVERLAY`) | Both: a real floating panel over any app, interactive (dictation's mic button, Enter to finish) | The user grants "Display over other apps" by hand in system settings; Play reviews this permission. A WebView in an overlay works but needs a Service to own it |
| **ChromeOS freeform windows** | Both: already floating windows on ChromeOS desktops | Not on top of other apps |
| **Notification** (ongoing, with actions) | Dictation status + stop | Not a panel; no live text worth reading |

Proposal: in Oriel, map `always_on_top` overlay windows on Android to an
overlay window when the permission is granted, with picture-in-picture as the
fallback for read-only ones (captions), and the page in the app as the last
resort. GhostPen asks for the permission from Settings when a float setting is
turned on, and explains what it's for. Dictation's main Android path stays the
keyboard / text selection anyway, so floating dictation there is a
nice-to-have.

## 2. Android

### Entry points

| Android | GhostPen | Oriel |
| --- | --- | --- |
| Text selection menu (`ACTION_PROCESS_TEXT`), also the right-click menu on ChromeOS | "GhostPen" opens a compact sheet over the current app (translucent activity on `#/actions`); the result **replaces the selection** when the field is editable (`EXTRA_PROCESS_TEXT`), else Copy/Share | **Gap**: `.android.process_text = .{ .label, .actions }`, an event with the text and read-only flag, and `finishWithText(text)` |
| Same, per action | Optional static entries for the top built-in actions ("Proofread", "Translate") — labels are fixed in the manifest, so custom actions only appear inside the sheet | Same gap, several aliases |
| Share sheet (`ACTION_SEND`) | text → Actions; URL → Summary; image → OCR | **Gap**: Android receiving for `oriel.share` (`.share_target`) |
| Quick Settings tile | Dictation (or Captions) | Exists, one tile; several tiles = gap |
| Floating captions / dictation | Picture-in-picture or an overlay window (see "Floating captions and dictation") | **Gap** |
| Launcher shortcuts (long-press icon) | Dictation, Playground, Meetings, Summarize link | **Gap**: static `shortcuts.xml` from build.zig (or app-level via `.android.sources`) |
| The Oriel keyboard | Later: a GhostPen keyboard with a mic (dictate into any field) and the actions on the field's text | Exists (`commitText`) |

### What doesn't apply on Android

Compile-time gated (`builtin.abi.isAndroid()`), with the matching settings
hidden: tray, global hotkeys, `oriel.input` copy/paste and the
snapshot/restore of the clipboard, overlay windows, the self-updater (APK
releases / F-Droid / Play instead), `ghostpen-cli`, the STT HTTP server.

### Features to check on a device

- AI over the network (Ollama on the LAN needs cleartext for local addresses:
  `network_security_config.xml`).
- Built-in models and Whisper through ggml (size and speed on a phone; smaller
  defaults).
- Dictation: the system recognizer or Whisper.
- Captions of other apps' audio: needs MediaProjection playback capture
  (Android 10+, and apps can opt out); mic-only otherwise.
- Meetings: mic recording in the foreground service.
- PDF export and Mermaid rendering in the WebView, file saving via the
  file provider / share.

## Application id

**`com.foreachdeveloper.ghostpen`** on every platform (decided), replacing
`dev.ghostpen.Oriel` (`build.zig` `.package.id`, `settings.zig` `app_id`)
before the first public APK, since Play can never change it. Desktop: a
one-time move of the old data dir (settings, models, meetings) to the new one
on first start, like the Tauri import.

## Build and release

- `build.zig`: an `.android` block (id, label, permissions, tile,
  later input method), `versionName`/`versionCode` from `build.zig.zon`.
- Commit `android/` (without `.gradle/`, `.kotlin/`, `app/build/`).
- `oriel android build` in CI on tags: arm64-v8a (+ x86_64 for
  emulators/ChromeOS), signed with secrets, APK attached to the release; the
  site's download table gets an Android row.

## Phases

1. **Single-window mode on desktop**: setting, `Shell`, router in
   `showWindow`, responsive pages, hotkey → Actions page with Replace (paste
   back), float settings for captions and dictation. Useful on its own and
   testable without Android.
2. **Android build that runs**: `.android` in build.zig, platform gates, app on
   the launcher in single mode, AI calls, Playground, Settings.
3. **Oriel: process text + share receive on Android** (Oriel release), then
   wire them here: selection menu and share sheet.
4. **Audio on Android**: dictation, meetings, Whisper/built-in models, the
   tile.
5. **Floating on Android** (Oriel: overlay window + picture-in-picture),
   playback-capture captions.
6. **Launcher shortcuts, CI release, site**; later the GhostPen keyboard.

## Android readiness (status, 0.4.0)

Done:
- Single app window: top app bar and drawer on phones, sidebar on wide
  Android (Chromebooks); Android styling (android.css); back navigation
  (drawer, sub-pages, sheets, start page); menus as bottom sheets.
- AI over the network, Gemini Nano profiles (`oriel.system_ai`), Android
  speech recognition for dictation, Android voices for Read aloud.
- Share in and out; meetings with other apps' audio or the microphone,
  playback with seeking (`oriel.media_scheme`), the speech model downloaded
  on save; microphone permission asked before capturing.

Left:
- Oriel: speaker labels (voice-detect on Android), the text-selection action
  (`PROCESS_TEXT`) returning the result, launcher shortcuts, floating
  captions/dictation (overlay / picture-in-picture).
- GhostPen: app id `com.foreachdeveloper.ghostpen` (+ desktop data move),
  `.share_target` routing (text → Actions, URL → Summary, image → OCR), a
  first run that doesn't assume Ollama, built-in models and PDF export
  checked on a phone, an APK in the release workflow.
